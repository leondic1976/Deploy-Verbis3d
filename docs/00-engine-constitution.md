# Verbis3D 엔진 개발 헌법

## 1. 프로젝트 정의

Verbis3D는 웹 브라우저에서 동작하는 독립형 3D 엔진 라이브러리다. 개발자는 코드 API로 객체를 생성·배치·변형·애니메이션화할 수 있고, 선택적으로 자연어 명령을 구조화된 엔진 명령으로 변환해 동일한 기능을 사용할 수 있다.

## 2. 절대 원칙

1. Three.js, Babylon.js, PlayCanvas 등 완성형 3D 엔진을 코어 구현에 사용하지 않는다.
2. 최초 렌더링 백엔드는 WebGL2로 구현한다.
3. WebGPU는 향후 별도 백엔드로 추가할 수 있도록 렌더링 추상화를 유지한다.
4. 수학, 장면 그래프, 객체 변환, 렌더링 명령, 리소스 수명주기를 엔진 내부에서 명시적으로 관리한다.
5. AI는 렌더링 코어에 직접 결합하지 않는다.
6. 자연어 명령은 반드시 검증 가능한 구조화 명령으로 변환한 뒤 실행한다.
7. 공개 API는 TypeScript 타입, 사용 예제, 테스트 없이 추가하지 않는다.
8. 전역 상태와 숨은 부작용을 최소화한다.
9. 엔진 코어는 React, Vue, Svelte 등 UI 프레임워크와 독립적이어야 한다.
10. 브라우저 표준을 우선하고 특정 브라우저 전용 기능은 격리한다.

## 3. 엔진의 중심 개념

Verbis3D의 중심은 화면이 아니라 **객체**다. 모든 3D 객체는 다음 속성과 행동을 일관된 방식으로 가진다.

- 고유 식별자와 이름
- 부모·자식 관계
- 위치, 회전, 크기
- 로컬 및 월드 변환 행렬
- 컴포넌트와 사용자 데이터
- 활성 상태와 생명주기
- 선택 가능한 렌더링 및 동작 기능

## 4. 계층 분리

```text
Application / Editor / User Code
              ↓
Public Engine API
              ↓
Scene · Object · Component · Animation
              ↓
Render Abstraction Layer
              ↓
WebGL2 Backend / Future WebGPU Backend
```

AI 계층은 Public Engine API와 Command Bus 사이에 위치한다.

```text
Natural Language
      ↓
AI Adapter
      ↓
Validated Command Schema
      ↓
Command Bus
      ↓
Public Engine API
```

## 5. 완료의 정의

기능은 다음 조건을 모두 만족해야 완료로 간주한다.

- 구현 코드 존재
- 공개 타입 정의
- 단위 테스트 또는 통합 테스트
- 최소 사용 예제
- 오류 조건 정의
- 문서화
- 기존 API와의 호환성 검토

## 6. 품질 기준

- 수학 연산은 입력 객체를 암묵적으로 변경하지 않는 방식을 기본으로 한다.
- 고빈도 렌더링 경로에서는 불필요한 객체 생성을 피한다.
- GPU 리소스는 생성과 해제 시점을 추적할 수 있어야 한다.
- 엔진 루프는 시간 간격을 초 단위로 전달한다.
- 모든 공개 함수는 예측 가능한 실패 방식을 가져야 한다.
- AI 결과는 신뢰하지 않고 스키마, 대상, 범위, 권한을 검증한다.

## 7. 범위 통제

초기 버전은 다음에 집중한다.

- 기본 수학 라이브러리
- 장면 그래프
- Transform 시스템
- Perspective Camera
- 정적 Mesh 렌더링
- 기본 Material과 Shader
- Engine Loop
- 구조화 명령 실행

초기 버전에서 제외한다.

- 완전한 게임 편집기
- 고급 물리 엔진
- 대규모 멀티플레이 네트워크
- 자체 3D 생성 AI 모델
- 영화 수준의 렌더링

## 8. 변경 원칙

이 문서의 절대 원칙을 변경하려면 변경 이유, 장단점, 기존 코드 영향, 마이그레이션 방안을 함께 기록해야 한다.
